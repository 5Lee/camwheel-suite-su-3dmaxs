# 3ds Max 视口导出插件设计

## 目标
- 为 3ds Max 制作一份独立插件，提供“当前活动视口导出 JPG”的快捷能力。
- 插件复用 3ds Max 自带的预览抓取导出流程，不自行实现一套截图/渲染导出器。
- 插件额外补足：
  - 快捷入口
  - 构图辅助线显示
  - 默认文件名 `场景名-时间戳.jpg`
  - 导出成功提示

## 已确认范围
- 平台：3ds Max
- 导出对象：当前活动视口
- 导出格式：JPG
- 导出方式：调用 3ds Max 原生导出链路
- 原生流程目标：
  - `工具`
  - `预览抓取窗口`
  - `创建预览动画`
  - 自定义范围 `0-0`
  - 视觉样式 `标准`
  - 明暗处理沿用系统首选项默认
- 入口：工具栏、右键菜单、独立小面板都提供
- 构图辅助线：
  - 不加边框
  - 不重复做 3ds Max 自带安全框
  - 只做视口构图辅助显示

## 不在首版范围
- 不重做渲染分辨率设置面板
- 不替代 3ds Max 自带安全框
- 不做物体拖拽吸附辅助线
- 不做导出 PNG / 其他格式
- 不做“带辅助线一起导出”的输出
- 不做视频预览导出，只封装单帧 `0-0`

## 总体方案

### 技术路线
- 首版优先使用 `MaxScript` 实现完整插件。
- 原因：
  - 入口注册更直接
  - 分发更简单
  - 对当前“视口导出 + UI 开关 + 辅助线叠加”需求足够
- 预留后续扩展空间：
  - 若将来需要更复杂配置、状态存储或图像处理，可再引入 `Python/pymxs`

### 导出架构
- 插件不直接做像素抓图核心逻辑，而是封装 3ds Max 原生预览抓取流程。
- 插件负责：
  - 触发当前活动视口导出
  - 固定为单帧范围 `0-0`
  - 尝试切到 `标准` 视觉样式
  - 生成默认文件名
  - 弹出保存流程
  - 导出成功/取消反馈
- 这样可以最大限度保持与宿主行为一致，降低兼容风险。

## 入口设计

### 1. 工具栏按钮
- 主按钮名称建议：
  - `CamWheel 视口导出`
- 点击行为：
  - 直接执行“导出当前视口”

### 2. 右键菜单
- 在右键菜单中挂一个 `CamWheel` 子菜单。
- 子菜单首版包含：
  - `导出当前视口`
  - `显示/隐藏辅助线`

### 3. 独立小面板
- 面板只放高频、低学习成本控件：
  - `导出当前视口`
  - `三分线`
  - `中心线`
  - `对角线`
  - `全部开启`
  - `全部关闭`
- 三个入口共享同一套内部动作，不做分叉逻辑。

## 构图辅助线设计

### 辅助线类型
- 首版支持三组：
  - 三分线
  - 中心十字线
  - 对角线

### 显示方式
- 只在当前活动视口中做叠加显示。
- 不创建场景对象，不写入模型。
- 不与 3ds Max 自带安全框重叠设计。
- 线条仅做细线显示，不加边框、不加蒙版。

### 导出关系
- 辅助线用于“看图辅助”，不进入最终 JPG。
- 这样可以保证：
  - 用户取景时有参考
  - 导出结果仍是干净视口图
- 如果后续需要“辅助线也导出”，应作为第二版单独扩展。

## 导出命名规则
- 默认文件名：
  - `场景名-时间戳.jpg`
- 时间戳格式建议：
  - `%Y%m%d-%H%M%S`
- 无已保存场景时，使用兜底名：
  - `camwheel-YYYYMMDD-HHMMSS.jpg`

## 导出交互流程
1. 用户从任意入口触发 `导出当前视口`
2. 插件读取当前活动视口
3. 插件准备原生预览抓取参数：
   - 范围 `0-0`
   - 视觉样式 `标准`
   - 明暗处理沿用宿主默认
4. 插件生成默认文件名
5. 弹出保存流程
6. 用户确认保存：
   - 调用原生流程生成 JPG
   - 成功后提示 `图片已导出`
7. 用户取消保存：
   - 不报错
   - 仅返回取消状态

## 状态模型
- 插件内部只需维护轻量状态：
  - `guides_visible`
  - `show_rule_of_thirds`
  - `show_center_cross`
  - `show_diagonals`
- 不需要维护复杂场景数据模型。
- 导出动作是无状态命令，只读取当前视口和当前辅助线显示配置。

## 模块拆分建议

### `main` / 注册层
- 负责：
  - 宏命令注册
  - 工具栏按钮注册
  - 右键菜单挂接
  - 面板打开入口

### `export` 模块
- 负责：
  - 执行“当前活动视口导出”
  - 封装原生预览抓取流程参数
  - 生成默认文件名
  - 导出成功/取消反馈

### `guide overlay` 模块
- 负责：
  - 在活动视口中绘制构图辅助线
  - 响应开关状态变更
  - 视口刷新时重绘

### `panel` 模块
- 负责：
  - 独立小面板 UI
  - 辅助线开关
  - 导出按钮触发

## 风险与约束

### 原生导出流程约束
- 3ds Max 原生预览抓取链路可用，但不同版本 API 细节可能有差异。
- 需要优先验证：
  - 是否能稳定以脚本方式触发
  - 是否能稳定写入 JPG
  - 是否能在脚本侧控制范围 `0-0`

### 视觉样式切换
- 将视口切到 `标准` 可能受当前视口模式、版本差异影响。
- 首版应把“设置标准视觉样式”当成尽力而为的步骤：
  - 成功则按目标行为执行
  - 失败则回落到当前视口显示，并提示用户

### 视口辅助线绘制
- 视口叠加绘制需要和 3ds Max 视口刷新机制配合。
- 首版应优先选择轻量、宿主兼容性好的叠加方式，不引入复杂 GPU 绘制依赖。

## 测试重点
- 工具栏按钮可触发导出
- 右键菜单 `CamWheel` 子菜单存在且动作可触发
- 独立小面板可打开并响应按钮/开关
- 默认文件名为 `场景名-时间戳.jpg`
- 取消保存不会报错
- 成功导出后弹出 `图片已导出`
- 三分线、中心线、对角线可独立显示/隐藏
- `全部开启 / 全部关闭` 正常
- 辅助线只用于视口观察，不进入最终 JPG
- 在未保存场景下仍能生成兜底文件名

## 建议实现顺序
1. 先做原生导出动作封装
2. 再加默认文件名与成功提示
3. 再接工具栏 / 右键菜单 / 面板三入口
4. 最后补视口辅助线叠加显示
